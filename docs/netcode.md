# 联机实现说明

> 状态：协议层 + 主机权威 + 客户端渲染已跑通，可双端实测。

## 一、架构

```
浏览器 A（房主）                 Node 服务器               浏览器 B（客户端）
  ├─ 完整模拟 sim.js  ──snap 15Hz──▶ 房间 ──▶ 转发 ──▶  只渲染快照
  ├─ 收 input/cmd     ◀──转发────── 房间 ◀────── 发 input 20Hz
  └─ 权威：伤害、掉落、经验         无游戏逻辑         只发输入，不改状态
```

服务器**不跑游戏逻辑**，只做房间与转发。因为 `sim.js` 是纯函数、随机数是可序列化种子，将来要把 host 搬进 Node 只需要把 `main.js` 的主机循环挪过去。

## 二、协议

**客户端 → 服务器**

| 消息 | 说明 |
|---|---|
| `{t:'join', room, name}` | 进房间，先到者成为房主 |
| `{t:'input', mx, my}` | 输入，20Hz，只转发给房主 |
| `{t:'cmd', c, a}` | 操作（加点/装备/购买/打造），只转发给房主 |

**服务器 → 客户端**

| 消息 | 说明 |
|---|---|
| `{t:'joined', id, host, room, players}` | 加入成功 |
| `{t:'peers', players}` | 玩家列表变化 |
| `{t:'host', id}` | 房主变更 |
| `{t:'snap', d}` | 实体快照（15Hz，只发给客户端） |
| `{t:'details', d, shop, stash}` | 玩家明细（2Hz，客户端 UI 用） |
| `{t:'full'}` | 房间满 |

**快照格式**（短键，坐标保留 1 位小数）

```js
{ t:'combat', pt:37.2, cy:2, near:0, k:1234,
  ps:[[id,x,y,hp,maxHp,face,alive,pickup]],
  es:[[id,x,y,hpPct,sprite,elite,boss,chill,burn]],
  ss:[[x,y,kind,vx,vy,spin]],
  gs:[[x,y,kind,rarity]] }
```

## 三、已实现

- 房间：4 人上限、房主自动选举（先到者）、房主离开自动移交
- 权限：只有房主能广播快照，客户端伪造会被服务器丢弃（已测）
- 客户端渲染：插值平滑（快照 15Hz → 渲染 60Hz）
- 玩家明细：装备/背包/天赋/金币/药水随 2Hz 下发，客户端 UI 可用
- 操作转发：客户端加点、购买、打造由房主代为执行
- 死亡：单人倒下不结束，全员倒下判负

## 四、验证方式

| 测试 | 内容 |
|---|---|
| `node test/net.js` | 10 条协议断言（加入/转发/权限/离开/房主移交/满员） |
| `node test/mp.js` | 10 条多人逻辑断言（独立输入/经验半径/装备独立/索敌） |
| `node test/hostbot.js` + `node test/shotclient.js` | 端到端：Node 房主机器人跑真实模拟，浏览器客户端渲染 |

端到端实测结果：客户端收到 68 帧/7 秒快照，血量、击杀、药水、技能图标全部同步。

## 五、启动方式

```bash
node server.js
# 房主：   http://localhost:8123/?room=TEST&host=1
# 队友：   http://localhost:8123/?room=TEST
```

房主进入后自动成为 host；其他人加入同一房间即可。

## 六、断线重连与房主迁移（已实现）

- 客户端在 sessionStorage 存一个 token，join 时带上
- 服务器把掉线玩家标记为 ghost 保留 30 秒，同 token 重连直接恢复原 pid
- 房主掉线 → 服务器立刻把 hostId 交给下一个在线玩家 → 该玩家用 iew.details（2Hz 下发的全体明细）重建 sim
- 已验证：
ode test/net.js 11/11，含「断线重连恢复原 pid（rejoin=1）」与「房主离开后自动移交」
