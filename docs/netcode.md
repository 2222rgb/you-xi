# 四人联机设计

> 目标：4 名玩家同屏合作割草，各自独立的技能 / 装备 / 等级，共享敌人、掉落与首领。

## 一、为什么现在就能做

`js/sim.js` 是**纯函数式**的：

- 不碰 DOM
- 不读 `Date.now()`，时间只来自传入的 `dt`
- 随机数是 `st.rngS` 一个整数种子，可序列化
- 所有实体都在 `st` 里，没有闭包外的隐藏状态

所以同一份 `sim.js` 既能跑在浏览器，也能 `require` 进 Node。**服务端不需要重写一套逻辑**，这是联机成本能压到最低的原因。

---

## 二、三种架构怎么选

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **主机权威**（推荐先做） | 一个玩家的浏览器跑完整模拟，其他人只发输入 | 开发量最小；延迟对 host 最优 | host 掉线即散伙；host 上传带宽是瓶颈 |
| **专用服务器** | Node 进程跑 `sim.js`，所有人都是客户端 | 公平、防作弊、可长期在线 | 要一台服务器；要处理房间生命周期 |
| P2P（WebRTC） | 无服务器 | 省钱 | NAT 穿透要 STUN/TURN，调试地狱 |

**路线**：先做主机权威（局域网/熟人局够用），协议设计成与传输无关，之后把 host 换成 Node 进程即可升级为专用服务器，客户端代码不用改。

---

## 三、数据模型

```js
st.players = [
  { id, name, x, y, hp, maxHp, level, xp, skills, gear, bag, ... }
]
```

现在 `st.player` 是单数。改造点是把它变成数组，并给所有"玩家相关"的逻辑加一个 `pid`：

| 逻辑 | 改造 |
|---|---|
| 移动 / 碰撞 | 每个玩家独立 |
| 技能释放 | 每个玩家独立冷却与索敌 |
| 敌人索敌 | 目标从"唯一玩家"改成"最近的玩家" |
| 拾取 | 谁先碰到归谁（XP 平分或归拾取者） |
| 升级 | 每个人独立弹三选一，**别人不暂停** |
| 镜头 | 各看各的；敌人只在任一玩家视野内才同步 |

联机的第一个设计决策就是**经验归属**。建议：击杀经验掉落为共享宝石，谁捡到谁得，但队伍共享一个"团队等级"用于难度缩放——否则四个人各练各的，节奏会散。

## 四、协议

传输层用 WebSocket（`ws` 包或手搓 RFC6455，约 150 行）。消息全部是 JSON 起步，后期换二进制。

**客户端 → 主机**

```json
{ "t": "input", "seq": 42, "mx": 0.7, "my": -0.7 }
{ "t": "pick",  "choice": 1 }
{ "t": "equip", "slot": "ring", "bagIndex": 3 }
```

**主机 → 客户端**（快照，15Hz）

```json
{ "t": "snap", "tick": 900, "ack": 42,
  "p": [[id, x, y, hp, flags], ...],
  "e": [[id, x, y, hpPct, type, flags], ...],
  "s": [[id, x, y, rot], ...],
  "k": [[x, y, value], ...] }
```

坐标用**整数 + 1/4 像素定点**，`hpPct` 用 0-255，一个敌人约 10 字节。

## 五、同步策略

| 项 | 做法 |
|---|---|
| 采样率 | 敌人 12–15Hz，玩家 20Hz |
| 客户端表现 | 快照之间线性插值，延迟 ~100ms 换取平滑 |
| 本地玩家 | 客户端预测（立即移动），收到快照后软校正 |
| 敌人 | 纯插值，不做预测（数量太多，预测会抖） |
| 伤害数字 | 客户端自己生成表现，主机只发"谁死了、掉了什么" |
| 掉线 | host 转移：按加入顺序选下一个玩家，把 `st` 序列化发过去 |

**带宽估算**：280 敌人 × 10 字节 ≈ 2.8KB/快照，15Hz ≈ **42KB/s/客户端**。四人局 host 上行约 126KB/s，家用宽带上行（一般 20–50Mbps）完全够；手机热点会吃力。

优化顺序：视野裁剪 → 只发改动的敌人 → 降到 12Hz → 二进制。

## 六、四步实施

| 步骤 | 内容 | 验收标准 |
|---|---|---|
| 1 | `st.player` → `st.players[]`，单机跑通 4 个假人 | 单机模式下 4 个角色同时动、各自升级 |
| 2 | 本地双开（两个浏览器窗口）通过 WebSocket 同步位置 | 能看到对方在动 |
| 3 | 共享敌人 + 快照插值 + 主机权威 | 两人打同一波怪，怪的血量一致 |
| 4 | 房间 / 匹配 / 断线重连 | 4 人开局到通关不崩 |

**不建议跳过第 1 步**：把多人数据模型先在单机里跑通，联机只解决传输，问题会少一个数量级。

---

## 七、风险

- **升级弹窗暂停**：单机是暂停的，联机不能暂停。需要改成"升级不打断战斗，卡片浮在角落等你点"。
- **拾取竞争**：四人抢宝石会很难受，建议经验共享。
- **主机优势**：host 零延迟，其他人 50–150ms。合作 PvE 可以接受。
- **作弊**：主机权威下，客户端只能改自己的显示，改不了真实伤害。可接受。

---

## 八、里程碑外的备选

如果四人联机太重，可以先做**同屏双人**（一个键盘两个角色）验证多人手感，再上网络。这个只要 1 天，而且能提前暴露"镜头怎么跟""经验怎么分"这些真问题。
